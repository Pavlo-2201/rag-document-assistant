# rag-document-assistant

Помощник, который отвечает на вопросы по русскоязычной документации MDN Web Docs
и показывает, из каких фрагментов документов взят ответ.

Архитектура (собирается по этапам):
documents → parser → chunking → embeddings → vector index → retriever → reranker → LLM → answer + sources.

## Данные

Корпус тот же, что в предыдущем проекте semantic-search-engine: 2570 русских
страниц MDN Web Docs (репозиторий [mdn/translated-content](https://github.com/mdn/translated-content)),
лицензия [CC-BY-SA 2.5](https://creativecommons.org/licenses/by-sa/2.5/), авторство —
MDN Web Docs contributors.

- Источник зафиксирован commit'ом `f39fd206b38a94264315eb2bcacb705bd8b5d326`
  (`configs/corpus.yaml`).
- Отбор страниц тот же, что в semantic-search-engine. После загрузки отпечаток
  корпуса считается его способом и сравнивается с опубликованным
  (`0f5e613e…`): **совпал**, то есть документы и их текст одинаковые
  (`data/corpus.meta.json`).
- В Git не попадают ни исходники страниц, ни результат разбора: только скрипты и
  метаданные.

## Команды

```bash
python scripts/download_corpus.py --config configs/corpus.yaml   # ~40 с, Markdown страниц
python scripts/ingest.py --config configs/corpus.yaml            # разбор → data/processed/documents.jsonl
python scripts/ingest.py --input-dir my_docs/ --output data/processed/my_docs.jsonl  # свои .md/.txt
python scripts/build_chunks.py --chunk-size 1000 --overlap 150   # → data/processed/chunks-c1000-o150.jsonl
python scripts/build_index.py --model e5-small   # FAISS по фрагментам → data/indexes/chunks-c1000-o150__e5-small
python scripts/build_index.py --model lsa-300
python scripts/eval_retrieval.py --retriever bm25 --retriever faiss:lsa-300 --retriever faiss:e5-small --split dev --split test
python scripts/ask.py "как разбить строку на части по разделителю"            # Qwen2.5-1.5B через llama.cpp
python scripts/ask.py --backend mock --retriever bm25 "что значит код 404"   # без модели: проверка связности
python scripts/eval_no_answer.py --split dev --refusal strict --retry-empty   # отказы на dev (~15 мин на CPU)
python scripts/eval_no_answer.py --split test --refusal strict --retry-empty
python -m pytest
```

## Фрагменты

Фрагмент — точный отрезок текста документа (`document.text[start:end]`) с
идентификатором `<doc_id>:<start>-<end>`, заголовком документа, путём разделов
и ссылкой на раздел. На всём корпусе проверено, что каждый фрагмент совпадает со
своим отрезком и что каждое слово документа попадает хотя бы в один фрагмент.

При `chunk_size=1000, overlap=150`: 16 890 фрагментов, медиана 766 символов,
дублирование текста из-за перекрытия 8 % (`data/chunks-c1000-o150.report.json`).

## Поиск по фрагментам

Компоненты semantic-search-engine используются без изменений: BM25, LSA,
sentence-transformers, индекс FAISS с соответствием позиция → id. Фрагмент для
них — документ, у которого id = `chunk_id`, а заголовок = «документ — раздел».
Индекс сохраняется вместе с кодировщиком и отпечатком набора фрагментов; при
загрузке на других фрагментах он отказывается работать (проверено тестом).

Запросы и разметка — из semantic-search-engine (`data/eval/sse/`, 36 dev и
36 test, разметка на уровне страниц; файлы скопированы без изменений, sha256
`32d20267…` и `26121a4a…`). Выдача фрагментов сворачивается в выдачу страниц
(страница получает позицию лучшего фрагмента), поэтому числа сравнимы с
поиском по страницам целиком. Параметры (вес заголовка у BM25) выбирались
только на dev.

| поиск (фрагменты c1000-o150) | dev R@1 | dev R@10 | dev nDCG@10 | test R@1 | test R@10 | test MRR@10 | test nDCG@10 |
|---|---|---|---|---|---|---|---|
| BM25 | 0.111 | 0.384 | 0.267 | 0.028 | 0.403 | 0.141 | 0.197 |
| `lsa-300`, FAISS flat | 0.056 | 0.310 | 0.194 | 0.056 | 0.361 | 0.187 | 0.210 |
| `e5-small`, FAISS flat | **0.218** | **0.722** | **0.488** | **0.139** | **0.542** | **0.331** | **0.336** |
| для сравнения: semantic-search-engine, страницы целиком, `e5-small` | 0.287 | 0.643 | 0.485 | 0.167 | 0.681 | 0.399 | 0.454 |

Машинная форма — `results/retrieval/*.json` (с выдачей по каждому запросу).

- `e5-small` по фрагментам лучше BM25 и LSA по фрагментам на обоих наборах.
- На уровне страниц поиск по фрагментам не лучше поиска по страницам целиком
  (test Recall@10 0.542 против 0.681, на dev наоборот 0.722 против 0.643);
  на 36 запросах это разница в несколько запросов. Фрагменты нужны не для
  поиска страницы, а чтобы передать модели нужный абзац, а не 70 000 символов;
  качество на уровне фрагментов (попал ли в выдачу абзац с ответом) измеряется
  на этапе разметки evidence spans.
- `lsa-300`, обученная на фрагментах, хуже, чем на страницах (0.361 против 0.569
  на test): на коротких текстах SVD получает меньше совместной встречаемости.

Стоимость индекса на CPU (4 ядра Xeon 2.1 ГГц): `e5-small` кодирует 16 890
фрагментов за 896 с, индекс 26.5 МБ; `lsa-300` обучается и кодирует за 40 с,
но вместе с сохранённым TF-IDF занимает 112 МБ (`data/indexes/*/build.json`).

## Генерация ответа

LLM-бэкенд заменяемый (`rag/llm.py`, протокол `LLMBackend`: `chat` и
`count_tokens`):

- `llama_cpp` — локальная Qwen2.5-1.5B-Instruct (GGUF q4_k_m) через
  llama-cpp-python на CPU, жадная генерация; платных API нет;
- `mock` — без модели: отвечает первым предложением первого фрагмента со ссылкой
  [1]. Нужен только для тестов связности; его ответы в таблицы качества не
  попадают (`Answer.is_mock`).

Как собирается ответ (`rag/generation.py`): поиск → top-5 фрагментов →
промпт, в который фрагменты добавляются по порядку, пока их суммарная длина в
токенах модели не превысит 2000 (не поместившийся фрагмент пропускается
целиком, а не обрезается) → ответ модели → разбор ссылок [n]. Ссылка на номер,
которого не было в промпте, удаляется из текста и записывается в
`invalid_citations`; в источники ответа попадают только процитированные
фрагменты из промпта, с адресом раздела документа.

Текст документов не может подменить инструкции: инструкции стоят только в
системном сообщении, фрагменты — в блоке `<sources>` пользовательского
сообщения и прямо названы данными, а теги, которыми фрагмент мог бы закрыть
блок (`</source>`, `<system>` и т. п.), экранируются (тест
`test_document_text_cannot_close_source_block_or_add_system_message`).

Промпт подбирался на 8 вопросах из dev (ответы просмотрены при разработке, без
метрик): с одними правилами в системном сообщении модель отвечала по существу,
но без ссылок; пример ответа в инструкции модель копировала как факт; номер
`[n]` внутри текста фрагмента она переписывала вместо ответа. Рабочий вариант —
правила в системном сообщении плюс короткое напоминание о формате в конце
вопроса и `repeat_penalty=1.1`.

Контрольный прогон на 12 вопросах dev (`results/generation/stage4-dev-sample.jsonl`,
`faiss:e5-small`, CPU): 7–26 с на ответ, поиск 15–40 мс, пять фрагментов занимают 980–1330
токенов, так что лимит в 2000 при top-5 не срабатывает. Видно, что ещё надо
делать: три ответа по существу, но без ссылок; два ответа состоят из одной
ссылки `[1]` без текста; один отказ пришёл со ссылкой («[1] В документах нет
ответа…»). На вопрос «как оставить в массиве только подходящие элементы» модель
отказалась, и это правильно: `filter()` не попал в найденные фрагменты.
Качество ответов на этом этапе не измерялось.

## Нет ответа

Вопросы без ответа — `data/eval/unanswerable.jsonl`: 24 вопроса (12 dev, 12 test)
двух видов: вне темы корпуса (Kubernetes, Swift, Svelte, Next.js, Android
Studio…) и отсутствующий факт рядом с темой (цена подписки MDN Plus, место
JavaScript в рейтинге TIOBE, сочетание клавиш в Яндекс Браузере…). У каждого
вопроса записаны слова, которых нет ни в одном из 2570 документов (проверено
поиском по тексту), поэтому ответа в корпусе точно нет. Вопросы с ответом — 36
dev и 36 test запросов из semantic-search-engine: у каждого в корпусе есть
размеченная страница с ответом (найдёт ли её поиск — другой вопрос).

Как система отказывается (`rag/generation.py`):

1. Порог близости лучшего фрагмента (`min_retrieval_score`): ниже порога —
   отказ без вызова модели.
2. Правило в промпте: если ответа во фрагментах нет, модель пишет ровно фразу
   «В документах нет ответа на этот вопрос.»
3. Разбор ответа модели. Отказ — ответ, в котором кроме фразы отказа и ссылок
   ничего нет; у отказа источников нет, даже если модель поставила ссылку. Если
   модель ответила по делу и добавила отказ про другой фрагмент («…[1]. [2] В
   документах нет ответа…»), предложение с отказом вырезается, ответ остаётся.
   Ответ из одних номеров («[1] [4]») — модель показывает, где ответ, но не
   пишет его; её переспрашивают один раз, и если снова пусто — отказ. Ответ без
   единой ссылки показывается с пометкой «не подтверждён документами».

Источники не выдумываются по построению: в источники попадают только номера
фрагментов, переданных в промпт, ссылки на другие номера вырезаются из текста.
Во всех прогонах этапа нет ни одного источника вне контекста
(`sources_outside_context = 0`); несуществующих номеров модель поставила 1 раз
на dev и 0 на test.

Вариант выбран на dev (48 вопросов), Qwen2.5-1.5B, поиск `e5-small`, top-5,
CPU (`results/no_answer/report__dev__*.json`, ответы по каждому вопросу — рядом):

| dev | с ответом (36): ответ со ссылками | ответ без ссылок | отказ (фраза / одни ссылки) | без ответа (12): отказ | ответ со ссылками | balanced accuracy |
|---|---|---|---|---|---|---|
| строгое правило отказа | 14 | 4 | 18 (10 / 8) | 11 | 1 | 0.708 |
| мягкое правило: отказ, только если ни один фрагмент не относится к вопросу | 13 | 1 | 22 (3 / 19) | 10 | 2 | 0.611 |
| **строгое правило + повтор при ответе из одних ссылок** | **16** | 5 | 15 (15 / 0) | 11 | 1 | **0.750** |

Balanced accuracy — среднее долей верных решений «отвечать / отказаться» в двух
группах; любой ответ на вопрос с ответом здесь считается верным решением, а
правильность самого ответа проверяется на этапе 2026-08-31.

- Мягкое правило оказалось хуже: модель стала ещё чаще отвечать одними номерами
  фрагментов. В пробе на 15 dev-вопросах другая формулировка того же правила
  давала обратный эффект: модель на 1.5B параметров очень чувствительна к
  словам промпта, поэтому выбор сделан по всему dev, а не по пробе.
- Порог по умолчанию выключен. Оценки `e5-small` сжаты в узкий диапазон:
  косинус лучшего фрагмента на dev 0.860–0.939 у вопросов с ответом и
  0.852–0.887 у вопросов без ответа; ни один порог не улучшил balanced accuracy
  на dev. Механизм оставлен (`--min-score`) и проверен тестом.
- Жадная генерация детерминирована: два независимых прогона на dev дали
  одинаковые ответы на 17 из 17 совпавших вопросов, поэтому вариант с повтором
  перезапускает только вопросы, где без повтора был ответ из одних ссылок.

Test, выбранный вариант, один прогон (`results/no_answer/report__test__strict__retry.json`):

| test | с ответом (36): ответ со ссылками | ответ без ссылок | отказ | без ответа (12): отказ | ответ со ссылками | ответ без ссылок | balanced accuracy |
|---|---|---|---|---|---|---|---|
| строгое правило + повтор | 18 | 5 | 13 | 9 | 1 | 2 | 0.694 |

Что видно:

- Отказ на вопросы без ответа держится в основном на модели: 9 из 12 на test.
  Ошибки: про Next.js и про сочетание клавиш в Яндекс Браузере модель ответила
  своими знаниями без ссылок (такой ответ помечен как неподтверждённый), а про
  Android Studio — со ссылками на реальные, но не относящиеся к вопросу
  фрагменты. Проверка ссылок ловит выдуманный источник, но не ловит ссылку на
  существующий фрагмент, который ответ не подтверждает.
- Обратная сторона строгого правила — 13 из 36 отказов на вопросы с ответом.
  Часть из них оправдана: нужного абзаца нет среди пяти найденных фрагментов.
  Разделение ошибок на поиск и генерацию — этап 2026-08-31.
- «Ответ со ссылками» ещё не значит «правильный ответ»: на «закрепить блок на
  месте при прокрутке» модель ответила про `background-attachment` со ссылкой на
  настоящий фрагмент. Правильность и обоснованность оцениваются отдельно.
- Генерация: медиана 12 с на вопрос на 4 ядрах CPU, максимум 44 с; повтор
  добавил 9 вызовов модели на 48 dev-вопросов.

## Этапы

| этап | дата | решение и почему |
|---|---|---|
| Ingest | 2026-07-06 | Хранится исходный Markdown, а не очищенный текст из semantic-search-engine: для ответа со ссылками нужны заголовки разделов (ссылка `url#якорь`, нарезка по разделам) и блоки кода (в них часто сам ответ). `doc_id` взят из semantic-search-engine (`mdnru-` + sha1(slug)), чтобы его разметка запросов подходила без пересчёта. Пакет `semsearch` скопирован без изменений, версия зафиксирована sha256 файлов. PDF не добавлен: в корпусе его нет |
| Chunking | 2026-07-13 | Размер в символах, а не токенах: нарезка не зависит от модели, лимит контекста LLM проверяется её токенизатором при сборке промпта. Фрагмент не пересекает границу раздела, если раздел помещается целиком, а короткие соседние разделы склеиваются: иначе получаются фрагменты из одного заголовка. Длинный раздел режется окнами с перекрытием по границе абзаца, строки или слова. Фрагмент — отрезок исходного текста с границами, поэтому связь с документом и проверка evidence span тривиальны |
| Embeddings, индекс, retriever | 2026-07-20 | Переиспользованы BM25, LSA, sentence-transformers и FAISS из semantic-search-engine: они там проверены тестами, а адаптер «фрагмент = документ» не требует их менять. Основная модель — `multilingual-e5-small` с префиксами `query:`/`passage:`: лучшая и там, и здесь. Индекс точный (flat): на 17 тыс. векторов поиск занимает доли миллисекунды, а приближённый индекс в semantic-search-engine ничего не выиграл. Качество меряется на уровне страниц, чтобы сравнить с предыдущим проектом на той же разметке |
| Генерация | 2026-07-27 | Локальная Qwen2.5-1.5B-Instruct в GGUF через llama.cpp: самая крупная модель, которая на 4 ядрах CPU отвечает за 10–20 с и прилично пишет по-русски; платные API не используются. Бэкенд заменяемый, mock проверяет связность без модели. Лимит контекста считается токенизатором модели, фрагменты не обрезаются. Номера источников назначает код, ссылки проверяются по списку переданных фрагментов |
| Нет ответа | 2026-08-03 | Отказ проверяется на отдельном наборе вопросов, ответа на которые в корпусе точно нет (их ключевых слов нет ни в одном документе). Отказ решает модель по строгому правилу в промпте; код разбирает её ответ: отказ без источников, ответ из одних ссылок переспрашивается, ответ без ссылок помечается. Источники берутся только из переданных фрагментов. Правило, повтор и порог выбирались только на dev; порог на оценке e5 не помог и выключен |
